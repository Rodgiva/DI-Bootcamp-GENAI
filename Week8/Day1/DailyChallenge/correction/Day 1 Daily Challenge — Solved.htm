TASK 1

Write load_texts()

What the challenge asks

Using requests to access the contents online, create a function load_texts(). It should receive a list of URLs, load them, clean non-words using regular expressions, and append the cleaned text to the corpus that will be returned.

Download and clean the three books
URLS = [
    "https://www.gutenberg.org/cache/epub/11/pg11.txt",      # Alice's Adventures in Wonderland
    "https://www.gutenberg.org/cache/epub/12/pg12.txt",      # Through the Looking-Glass
    "https://www.gutenberg.org/cache/epub/29042/pg29042.txt" # A Tangled Tale
]

def clean_bounds(text):
    """Cut off Gutenberg's licence header and footer."""
    start_idx = text.find('*** START')
    end_idx   = text.find('*** END')
    if start_idx != -1 and end_idx != -1:
        text = text[start_idx:end_idx]
    return text

def normalize(text):
    text = clean_bounds(text)
    text = re.sub(r'[^A-Za-z\s]', ' ', text)   # keep letters and spaces, nothing else
    text = re.sub(r'\s+', ' ', text).strip()   # squeeze runs of whitespace into one space
    return text

def load_texts(urls):
    corpus = []
    for url in urls:
        resp = requests.get(url, timeout=30)
        resp.raise_for_status()
        corpus.append(normalize(resp.text))
    return corpus

texts = load_texts(URLS)
print([len(t) for t in texts])
What the code does
  1. resp.raise_for_status() — turns a silent failure into a loud one. Without it, a 404 page becomes a “book” and you analyse an error message for the rest of the notebook.
  2. re.sub(r'[^A-Za-z\s]', ' ', text) — the ^ inside the brackets means not. So: anything that is not a letter or whitespace becomes a space. Digits, punctuation, apostrophes, chapter numbers, all gone.
  3. re.sub(r'\s+', ' ', text) — the step above leaves long runs of spaces behind. This collapses each run to a single space.
  4. corpus.append(...) — one cleaned string per book, returned as a list. The challenge asks for exactly this shape, and every later step assumes it.
What you should see
[135578, 152673, 144271]
What the apostrophe rule costs you

Alice's becomes alice s — the apostrophe is not a letter, so it is replaced by a space and the word splits in two. You end up with thousands of stray one-letter tokens.

They disappear in Task 4 by luck rather than design: NLTK's stopword list happens to contain s, t, d, ll, m, re and ve. Worth knowing why they vanished, because with a different stopword list they would not.

Why this step exists

Everything downstream — tokens, stems, word clouds, TF-IDF — is computed from these three strings. Cleaning is not housekeeping; it is the step that decides what your analysis is even able to see.

What that check does and does not prove

All zeros looks like success, and it is — but it is a weak test. You filtered with that list and then asked whether the list is gone. It could only ever return zero.

It catches one real bug: forgetting .lower() in Task 3. Then I and Me survive, the counts stay zero anyway, and the check passes while the data is wrong. The honest check is the token count — 29,465 down to 12,106 tells you something actually happened.

One thing stopword lists quietly destroy

not, no and never are all stopwords. In a search engine or a sentiment model, deleting them turns a phrase into its opposite. For word-frequency work like today it is harmless. Stopword removal is a decision about the task, not a fixed rule.

Why this step exists

Roughly half of all English text is stopwords. Dropping them cuts the data in half and removes words that appear in every document and therefore distinguish nothing.

Lemmatize with spaCy

What the challenge asks

Use the spaCy pre-trained model en_core_web_sm to load and print the first 50 lemmatized tokens.

Hint: in spaCy the lemmatized token can be accessed as an attribute.

Reduce every word to its dictionary form
lemmatized_tokens = []
for text in texts:                      # note: the ORIGINAL text, not the token list
    doc = nlp(text)

              if tok.is_alpha and tok.text.lower() not in stop_words]

What the code does

  3. tok.is_alpha and the stopword test — the same filtering as Task 4, applied here because this path starts from the raw text again.
  4. this cell is slow — a minute or two for three books. It is running a trained neural model over every sentence, not looking words up in a table.

Look closely — the lemmas are not perfect either

adventures and tears came back unchanged. In an ordinary sentence spaCy turns tears into tear. Here it does not.

Because of Task 1. Stripping punctuation and the title case left spaCy reading ALICE S ADVENTURES IN WONDERLAND, where it tags ADVENTURES as a proper noun — a name — and spaCy deliberately leaves names alone. Feed it a real sentence and tears → tear as expected.

The lesson is worth more than the task: lemmatization is only as good as the grammar you leave it to read. Aggressive cleaning destroys the signal the lemmatizer depends on.

The answer, in three sentences

Stemming chops, lemmatizing looks up. Porter applies fixed suffix rules with no knowledge of English, so it produces alic and adventur — fast, crude, and not words.

Lemmatizing uses a dictionary plus the word's job in the sentence. spaCy first decides that tears is a noun, then returns the noun's dictionary form. The output is always a real word.

So: stems for machines, lemmas for humans. Use stemming when only your code reads the output and speed matters; use lemmatization when a person will see it, or when a later step needs real words.

Why this step exists

This is the only task today with no code to get right and a written answer to get right instead. It is also the one most students answer with a definition instead of an observation.

TASK 9

Identify the named entities — and explain the empty result

What the challenge asks

Using NLTK, identify all the entities of each text.

Find the names in the text
def extract_entities(tokens):
    tagged = pos_tag(tokens)
    tree = ne_chunk(tagged, binary=False)
    ents = []
    for chunk in tree:
        if hasattr(chunk, 'label'):           # a named entity is a subtree, not a leaf
            ent_text = ' '.join(c[0] for c in chunk.leaves())
            ents.append((ent_text, chunk.label()))
    return ents

for i, tokens in enumerate(filtered_tokens):
    ents = extract_entities(tokens[:500])
    print(f'Book {i} entities (sample): {ents[:30]}')
What the code does
  1. ne_chunk — takes POS-tagged words and groups consecutive ones into named entities: PERSON, GPE (a place), ORGANIZATION.
  2. hasattr(chunk, 'label') — the result is a tree. Ordinary words come back as plain (word, tag) tuples; entities come back as subtrees, and only subtrees have a .label(). This line is how you tell them apart.
  3. chunk.leaves() — the words inside one entity, so a two-word name like White Rabbit is rejoined into a single string.
What you should see
Book 0 entities (sample): []
Book 1 entities (sample): []
Book 2 entities (sample): []
Three empty lists. This is the most valuable result in the challenge

Nothing is broken and your code is correct. NLTK's entity recogniser depends almost entirely on capital letters, and you removed every one of them with .lower() back in Task 3.

Capitalised : [('Alice', 'PERSON'), ('White Rabbit', 'FACILITY'),
               ('London', 'GPE'), ('Lewis Carroll', 'PERSON')]

Four entities, then none. Same sentence, same code, one .lower() apart.

TASK 11

Five most frequent words with Bag of Words

What the challenge asks

Use the BoW method to check the five most frequent words in all the books.

Hint: which text from the preprocessing step will work best — raw text, stemmed, lemmatized?

Count every word in every book
lemmas_joined = [' '.join(toks) for toks in lemmatized_tokens]   # the hint's answer

cv = CountVectorizer(min_df=1)
bow = cv.fit_transform(lemmas_joined)
vocab = cv.get_feature_names_out()

bow_df = bow.toarray()
totals = bow_df.sum(axis=0)              # add the three books together
top_idx = totals.argsort()[::-1][:5]     # sort ascending, reverse, take five
top_words = [(vocab[i], totals[i]) for i in top_idx]

print('Top 5 words overall (BoW):', top_words)
print('\nBoW matrix shape:', bow_df.shape)
What the code does
  1. CountVectorizer — builds the vocabulary from all three books, then counts each word per book. One row per book, one column per word.
  2. .toarray() — the result is a sparse matrix, which stores only the non-zero cells. This expands it to an ordinary grid. Fine for 3 books; never do it to a million.
  3. totals = bow_df.sum(axis=0) — axis=0 sums down the columns, giving one total per word across all three books.
  4. argsort()[::-1][:5] — argsort returns positions, smallest first; [::-1] flips it; [:5] takes the top five. Memorise this idiom, it is everywhere.
What you should see
Top 5 words overall (BoW): [('say', 1309), ('alice', 872), ('one', 474), ('go', 437), ('get', 314)]

BoW matrix shape: (3, 4606)
The hint's answer, and why

Use the lemmatized tokens. Raw text keeps say / says / said as three separate words and splits their counts. Stemmed text would group them correctly but the chart would read alic and adventur.

Lemmas give you correct grouping and readable labels. That is the whole answer, and it is why the pie charts two tasks from now are legible.

Why this step exists

Bag of Words is the first real text-to-numbers step. Order is thrown away — the queen beheaded the knave and the knave beheaded the queen give identical rows — and in exchange you get a table you can do arithmetic on.

  2. each line reads (document, column)  count. Only non-zero cells are stored — that is what sparse means, and it is why a 3×4606 matrix does not print 13,818 lines.
  3. vocab[idx] — turns a column number back into the word. The vocabulary is alphabetical, so column 0 is the alphabetically first word, not the most frequent.
What you should see
  (0, 3214)	8
  (0, 1286)	3
  (0, 4102)	1
  ...

Reading one row by hand:
  doc 0, column   379 -> "alice" appears 403 times
  doc 0, column  3665 -> "say" appears 478 times
The answer, in the task’s own words

Document number — the first number in the bracket. The row: which book. (0, ...) is Book 0.

Index — the second number. The column: which word. Look it up with cv.get_feature_names_out()[index].

The count — the number after the tab. How many times that word appears in that book.

So (0, 3214) 8 reads: in Book 0, the word at column 3214 appears 8 times.

Why this step exists

This is the task that separates copying from understanding. Nearly every text-ML library hands back a sparse matrix, and if you cannot read one you cannot debug anything downstream.

TASK 14

Are these words informative?

What the challenge asks

Analyse the outputs: are those words informative? Are they insightful or expected?

The answer

No. They are expected, and that is exactly the problem.

say tops all three books. alice tops two. one, go, little fill the rest. You learned that these are books in which a character called Alice talks — which you knew from the titles.

The words that win are the ones that appear everywhere, and a word that appears everywhere cannot tell two documents apart. Counting rewards exactly the wrong thing.

Part C · Tasks 15–16

Solving the frequency problem with TF-IDF

A word that appears in every document is not evidence. Weight each word by how rare it is across the corpus, and the books start telling you apart.

TASK 15

Build the TF-IDF matrix

What the challenge asks

Create another BoW, now using TF-IDF as vectorizer.

Hint: you need to pass min_df=1, max_df=2 as arguments of TfidfVectorizer(), because we are using a small dataset.

Weight each word by how rare it is
tfidf = TfidfVectorizer(min_df=1, max_df=2)
tfidf_mat = tfidf.fit_transform(lemmas_joined).toarray()
vocab_tfidf = tfidf.get_feature_names_out()

print('BoW vocabulary  :', len(vocab))
print('TF-IDF vocabulary:', len(vocab_tfidf))
print("'alice' still in the vocabulary?", 'alice' in set(vocab_tfidf))

for doc_id, row in enumerate(tfidf_mat):
    top = row.argsort()[::-1][:5]
    pairs = [(vocab_tfidf[i], round(float(row[i]), 4)) for i in top]
    print(f'Book {doc_id} top TF-IDF words:', pairs)
What the code does
  1. TfidfVectorizer — same counting as before, then each count is multiplied by an inverse document frequency weight: high for words in few documents, low for words in many.
  2. min_df=1 — keep a word even if it appears in only one book. With three documents you cannot afford to throw anything away.
  3. max_df=2 — drop any word that appears in more than 2 of the 3 books. This is the line that does the work, and it is why the hint exists.
  4. the rest is the same argsort idiom as Task 11, applied to scores instead of counts.
What you should see
BoW vocabulary  : 4606
TF-IDF vocabulary: 3290
'alice' still in the vocabulary? False

Book 0 top TF-IDF words: [('turtle', 0.3147), ('mock', 0.2735), ('hatter', 0.2201),
                          ('gryphon', 0.2149), ('duchess', 0.1882)]
A trap in this exact setup

Because max_df=2 deletes words, vocab_tfidf is shorter and differently ordered than vocab from Task 11. Index 379 is no longer alice.

Reusing the old vocab here gives you plausible-looking labels that are completely wrong, with no error message. Always look up names with the vectorizer that produced the matrix.

What max_df=2 really does — and why it is a blunt instrument

With 3 documents, max_df=2 means: if a word appears in all three books, delete it from the vocabulary entirely. Not downweight — delete.

That is why alice is simply gone. It is in all three books, so it fails the filter. Same for say, one, go — and, incidentally, for project, gutenberg and ebook, which is why the Task 2 boilerplate never showed up in your results.

On a real corpus you would not do this. With thousands of documents the IDF weighting handles common words gracefully on its own. With three documents the maths has almost nothing to work with, so the hint reaches for a crude filter instead. Say that in your write-up.

Why this step exists

TF-IDF is the single most useful idea in classical text analysis, and this task is where you see why in one line of output. The top words stop being say and alice and start being the things each book is actually about.
