2

See that a model is just a file

In plain words

“Open weights” means the model's file is published for anyone to download and run forever. “Closed” (ChatGPT, Claude, Gemini) means the file stays on their servers and you rent access through a window.

Open huggingface.co, search “Qwen3 GGUF”, open the Files tab.

What you're looking at
  1. Hugging Face is “GitHub for models” — where open models are published.
  2. A file like qwen3-...-Q4_K_M.gguf (a few GB) is the model — nothing else needed.
  3. Inside are billions of learned numbers (“weights”). “7B” = seven billion of them.
Checkpoint — what you should see
You can see the .gguf files and their sizes. A whole model is ~a few GB — smaller than one season of a show.

Terminal

Terminal — only if you have 16 GB RAM (second tab)

In plain words

ollama runs model files (like a music player); the .gguf is the song. pull downloads from a registry — just like docker pull or npm install. qwen3:0.6b = family Qwen3, size 0.6 billion weights.

Checkpoint — what you should see
A progress bar fills to 100%. That bar is ~600 million learned numbers arriving on your laptop.
Watch out

Corporate laptop blocks the install? The hosted provider (Lab 1) covers every lab — same API shape. Slow wifi? 0.6b is tiny on purpose; nobody waits more than ~3 min.

5

The six questions (pick any model)

In plain words

The leaderboard changes every ~8 weeks, so don't memorise models — memorise the six questions that never expire.

Before you pick a model, ask:
  1. Task — what job is it doing?
  2. License — can you legally use it? (MIT / Apache = do-anything; others may cap commercial use.)
  3. Hardware — does it fit your machine?
  4. Latency — interactive UI or batch?
  5. Quality bar — does it really need to beat the frontier, or is “good enough” fine?
  6. Hosting — your laptop, your server, or a hosted provider?
Checkpoint — what you should see
Say them back without looking. Walk the drill: an internal HR chatbot on sensitive data, 200 users, small budget → self-hosted, MIT/Apache, mid-size 7–13B, good-enough quality.

Lab 1 — hosted bake-off (20 min)

In plain words

Hosted providers (Groq / Together / Hugging Face) run the big models for you via an API key. Great for comparing flagships you can't fit on a laptop.

In your hosted provider, pick three models from three families and run the same prompt on each. Rank them for THIS task; note latency, quality, length.

The prompt
Explain how Mixture of Experts (MoE) works in exactly 3 bullets,
plain English, no jargon, each bullet under 25 words.
Suggested picks — pick 3 in the dropdown
# Groq retires models often - current ids: console.groq.com/docs/models
openai/gpt-oss-120b      # OpenAI (open-weight)
qwen/qwen3.8-27b         # Qwen
allam-2-7b               # SDAIA (Arabic + English)
As you go
  1. First write your predicted winner (a bet) — upsets are common.
  2. Note: there's no single best model — only the best fit for your specific task.
  3. If a model is missing from your provider, that's a finding too: availability is part of picking.
Checkpoint — what you should see
Three rankings across the room will disagree — that's the point. The bake-off beats the leaderboard for your task.
7

Match model to your machine

In plain words

Quantization compresses weights to 4-bit (“Q4” in the filename) — ~4× smaller, barely dumber. It's JPEG for neural networks, and it's why a few-GB file holds billions of numbers.

Find your row and pick a model
  1. 8 GB RAM, no GPU: up to ~3B at Q4 — you already have qwen3:0.6b. Zero shame; every lab works on it.
  2. 16 GB RAM: the sweet spot — mistral:7b or llama3.1:8b.
  3. Discrete GPU (8+ GB VRAM): ~13B is in reach.
  4. Apple Silicon: unified memory punches above its weight.

Rule of thumb: a 7B model at Q4 needs roughly 4–5 GB of RAM/VRAM.

Checkpoint — what you should see
You can name the model you'll drive in Lab 2 and why it fits your laptop.

Lab 2 — Python + Ollama ladder (25 min)

In plain words

Ollama exposes an OpenAI-compatible API on localhost:11434. Learn that one request shape and the same code drives a local model OR any cloud — you change one line.

First, confirm Python can reach Ollama:

Pre-flight check
import requests
r = requests.get('http://localhost:11434/api/tags', timeout=5)
print([m['name'] for m in r.json()['models']])

Then the helper — climb the rungs, no pressure to finish:

The helper (Rung 1: run it)
import requests

def ask(prompt, system=None, temperature=0, model="qwen3:0.6b", max_tokens=400):
    msgs = ([{"role": "system", "content": system}] if system else []) \
         + [{"role": "user", "content": prompt}]
    r = requests.post(
        "http://localhost:11434/v1/chat/completions",   # OpenAI-compatible, but LOCAL
        json={"model": model, "messages": msgs,
              "temperature": temperature, "max_tokens": max_tokens,
              "reasoning_effort": "none"},   # qwen3 thinks first; "none" = answer now
        timeout=300)
    return r.json()["choices"][0]["message"]["content"]

print(ask("Say hi in 3 languages, one per line."))
Climb the ladder
  1. Rung 1 — run the script, get your first Python-driven local reply.
  2. Rung 2 — add a system message (your Day-1 six-ingredient frame).
  3. Rung 3 — force JSON out (below).
  4. Rung 4 — point the same code at your hosted provider; compare latency + quality.
  5. Rung 5 — swap model="mistral:7b". Same code, zero other changes.
Rung 3 — force JSON (Day-1 skill, local model)
SYSTEM = """You output ONLY valid JSON. No prose. No markdown fences.
Schema: {"sentiment": "pos"|"neg"|"neu", "confidence": number 0.0-1.0}
Example: {"sentiment":"neu","confidence":0.7}"""

import json
raw = ask('Classify: "Loved the coffee, hated the wait."', system=SYSTEM)
# small models often wrap JSON in ```fences``` even when told not to - strip them:
raw = raw.strip().removeprefix("```json").removeprefix("```").removesuffix("```")
print(json.loads(raw))
Checkpoint — what you should see
You see a JSON object printed from a model on your laptop. Small 0.6b models often wrap JSON in ```fences``` — the code above strips them before json.loads. Cleaner still: Ollama's own library forces the shape with format=schema (see lab-solutions/lab2_ollama_native.py).
Pitfall

requests missing → pip install requests. Port already in use → Ollama's already running, skip ollama serve. Empty reply from qwen3 → it's spending the budget on hidden thinking; the helper's reasoning_effort: "none" turns that off. Still empty → bump max_tokens.

WRAP

Agents teaser + where next

Models answer; agents act — call tools, loop, work multi-step. Four names to recognise:

  • MCP — the wiring standard between any model and any tool. Later this week you'll build an MCP server and your local model becomes its engine.
  • LangGraph — workflows as graphs; the production choice.
  • CrewAI — agents as a team with roles; the easy start.
  • Pydantic AI — type-safe agents; today's JSON skill, weaponised.

The honest trade: local is private, free, offline, yours; hosted is stronger, faster, zero-ops. Pros use both — the six questions tell you when. And remember: the model table goes stale by autumn; the capability and the six questions don't.
